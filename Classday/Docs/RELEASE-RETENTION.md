# 全局发布规则（适用于 F:\vebcoding 下所有项目）

> 生效日期：2026-11-18 · 由 YG 定，所有项目、所有会话都必须遵守。

## 规则：新版本发布时，备份上一版 + 清理旧版本

每次交付/发布一个新版本时，按顺序执行：

1. **备份上一版**：把上一个大版本的全部产物打包成
   `artifacts/_backup/<上一版版本号>.zip`（含 sha256 清单），确认压缩包可解开、文件数对得上。
2. **删除更早的所有版本**：所有比「上一版」更旧的版本目录、单文件产物、临时调试目录，**全部删除**。
3. **保留集合**（再次发布会轮转）：
   - 当前版本目录 `artifacts/<当前版本>/`（含 IPA/APK/截图/校验值）
   - 上一版备份 `artifacts/_backup/<上一版>.zip`（**只留 1 份**，再下一版发布时被替换）
   - `artifacts/_backup/` 目录本身
4. **散落产物归位**：项目根或 artifacts 根下的临时文件（`tmp-*`、`*.log`、测试截图等）
   要么归进当前版本目录，要么删除，不留散件。
5. **记录**：在当前版本目录写 `RELEASE-NOTES.md`（版本号、构建号、提交、产物清单 + sha256、
   以及「已备份并删除」的旧版本列表），便于回溯。

## 执行方式

```powershell
# 以当前版本号运行，自动备份上一版并清掉更旧的
F:\vebcoding\ClassDay\build-tools\release-prune.ps1 -ProjectRoot F:\vebcoding\ClassDay -CurrentVersion 2.10.4
```

脚本行为：
- 找到版本号最高的「非当前」目录 = 上一版 → 打包到 `_backup/<版本>.zip`
- 删除所有其它旧版本目录与散落文件
- 打印保留清单 + 释放空间

## 注意

- 备份包里必须含**可交付产物本体**（ipa/apk/exe 等），不能只有截图或日志。
- 用户自己的 `Downloads` 目录不在自动清理范围内（那里是用户手上下载的副本），
  如需要清理会先明确告知。
- 版本号比较按语义化版本（2.10.4 > 2.10.10 按段比较，不按字符串）。
